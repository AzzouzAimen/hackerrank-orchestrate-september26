# Semantic benchmark scorer completed — 2026-09-12

`semantic_benchmark_scorer.py` and `score_semantic_benchmark.py` score a saved seven-fact `EvidenceBundle` against a frozen development case, all 14 development cases, or the holdout set only when the CLI explicitly requests it. They make no model calls. The scorer pins both frozen reference SHA-256 values, verifies each case's saved runtime manifest and exact payload hash, and uses only that payload for evidence ownership and target provenance.

Results contain the Pydantic parse result, output availability, each required meaning and its matched fact, accepted canonical or frozen-permitted alternate representation, missing facts, unsupported claims, unknown-preservation errors, and harmful errors. The summary counts passed cases and meanings, failures by category, fact type, dimension, harmful error, and unknown error. Missing output and empty facts fail cases with meaningful evidence. Matching uses a maximum-weight one-to-one assignment rather than full JSON equality; equivalent numeric spellings and the frozen development alternate forms are accepted. Optional structured raw-event restatements are accepted only when the cited event proves their status, value/date, or link. Image values require the annotated image meaning.

Development-only behavioral tests cover all 14 canonical bundles, the ended-stream history-ID and contingent-bonus alternatives, empty and unavailable output, missing meaning, wrong target, invented unknown amount/date/currency/event ID, wrong lifecycle and image meaning, gross-total-as-due harm, supported and unsupported extras, schema rejection, and CLI output.
