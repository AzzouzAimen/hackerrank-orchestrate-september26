## Rejected or ambiguous pending review

Reject exact/near duplicates that only repeat a template; any image whose readable fields cannot be independently confirmed; cases where event linkage and message semantics conflict; cases requiring inferred amounts/dates; and rare instruction-like, duplicate, or cancellation categories without defensible evidence. Several message families are multilingual or templated; retain them only when a reviewer can read and defend the meaning. No final rejection is asserted until manual review.

## Verification and differences from proposal

The manifest stores source SHA-256 hashes, real IDs and modalities. A read-only implementation leaves dataset files untouched. Compared with the proposal, the inventory confirms broad coverage for pending refunds, transfers, retries, non-cash investments and prize lifecycle; it also shows that most examples are repeated templates, so split assignment must be family-aware. Clean instruction-injection and duplicate examples should not be fabricated.

## Recommendation

Manually inspect the listed evidence bundles, resolve language/template and linkage ambiguities, then record a reviewed candidate table and freeze the development/holdout manifest. Do not run models or build final semantic annotations until that review is complete.
